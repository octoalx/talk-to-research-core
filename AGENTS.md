# Правила для агента

Репозиторий с кодом ядра MVP. Что строим и почему — в журнале
[octoalx/talk-to-research](https://github.com/octoalx/talk-to-research): `spec/` и `decisions/`.
Пошаговый план — [docs/PLAN.md](docs/PLAN.md) (копия `spec/12-implementation-plan.md`).
Язык документации, отчётов и сообщений коммитов: русский.

## Порядок работы

1. Идти по вехам M0 → M9 строго по порядку. Веха делается одним или
   несколькими небольшими PR (одна цель — один PR, decisions/028);
   человек смотрит и сливает.
2. Веха готова, только когда выполнены все её проверки «Готово, когда»,
   прошли `make check` (линтер, типы, тесты) и, начиная с M5, прогон
   проверочного набора без ухудшения метрик прошлой вехи.
3. Сначала тест, потом код: для каждой вехи сначала пишутся тесты из
   раздела «Проверки», потом реализация.
4. Эталоны (`eval/`) не менять, чтобы тест прошёл. Если эталон кажется
   неверным, записать это в `docs/feedback.md` и спросить человека.
5. Версии библиотек и имена моделей из этого плана — на октябрь 2026 и
   могут устареть. Перед установкой проверить актуальные версии и
   записать выбранные в `docs/stack.md` с датой.
6. Если шаг упирается в неизвестное (разметка сайта, поведение модели),
   сделать минимальный замер, записать результат в `docs/results/` и
   выбрать вариант по умолчанию из плана. Не останавливаться молча.
7. Ничего не отправлять в сеть, кроме скачивания моделей, библиотек и
   актов с pravo.by. Документы пользователя не покидают компьютер.
8. Каждая функция ядра доступна из командной строки: так её можно
   проверить без интерфейса.
9. Связь с журналом (decisions/025): перед каждой вехой сравнить коммит
   журнала в `docs/journal.md` с текущим `main` журнала и перенести
   изменения `spec/12` и новых решений в `docs/PLAN.md`. Замеры писать в
   `docs/results/`, вопросы и расхождения с планом — в `docs/feedback.md`.
   В репозиторий журнала не писать.

## Проверки и зависимости

- Проверки: `make check` (ruff, mypy, pytest без меток `mac` и `model`). Они же
  идут в песочнице Factory без сети.
- Тесты, которым нужен Mac, помечать `@pytest.mark.mac`; нужна настоящая модель —
  `@pytest.mark.model`. Для остального — поддельные модели из `core.llm` и `core.embed`.
- Зависимости MVP уже в `pyproject.toml`; тяжёлые — в группе `heavy`. Новую
  зависимость добавляет человек отдельным PR (decisions/028).

## Файлы для связи с журналом

- `docs/journal.md` — коммит журнала, по которому сейчас сверен план.
- `docs/results/` — отчёты замеров по вехам.
- `docs/feedback.md` — вопросы и расхождения с планом для журнала.
